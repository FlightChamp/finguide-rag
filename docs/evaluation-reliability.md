# 평가를 어떻게 신뢰하는가

> README 4번 섹션 초안. 기존 README에 붙여넣어 사용.
> 수치는 2026-08-23 측정 기준.

이 프로젝트에서 가장 많은 시간을 쓴 곳은 검색기나 생성기가 아니라 **평가기**다.
지표를 만들고, 그 지표를 믿을 수 있는지 다시 측정하고, 믿을 수 없는 항목은
자동화 대상에서 제외했다. 아래는 그 과정의 기록이다.

---

## 4.1 자체 지표는 임의 정의가 아니다

생성 단계에서 쓰는 네 지표는 이름만 도메인에 맞췄을 뿐, 정의는 공개 벤치마크의
분류 체계에 대응한다.

| 자체 지표 | 대응하는 표준 개념 | 출처 |
|---|---|---|
| 수치오류 | Evident Conflict (숫자 오류 하위 유형) | RAGTruth (Niu et al., 2024) |
| 상품불일치 | Evident Conflict의 금융 도메인 하위 유형 | 동일 |
| 환각 | Introduction of Baseless Information / Faithfulness의 여집합 | RAGTruth · RAGAs |
| 오거절 | Over-refusal (abstention 문헌) | RGB (Chen et al., AAAI 2024) 외 |

거절 단계의 지표도 마찬가지다. RGB 벤치마크는 RAG의 기본 능력 중 하나로
**negative rejection**(검색 근거가 불충분할 때 답변을 유보하는 능력)을 정의하며,
이 프로젝트의 거절 로직은 그 능력을 구현하고 측정한 것이다.

RAGTruth의 기준을 그대로 따랐다는 점도 밝혀둔다. **세상 기준으로 참이더라도
검색된 근거가 뒷받침하지 않으면 환각으로 라벨링한다.** 은행 창구 직원이 원문
근거로 안내해야 하는 B2E 환경에서는 이 기준이 맞다.

  <https://aclanthology.org/2024.eacl-demo.16/>

## 4.2 표준 지표를 실제로 돌려서 대조했다

"우리 지표가 표준과 대응한다"는 주장만으로는 부족하다고 보고, RAGAs의 두 지표를
같은 데이터에 직접 계산해 사람 라벨과 대조했다.

**구현 방식** — 라이브러리를 호출하지 않고 원논문 정의대로 구현했다.

- *Faithfulness*: 답변에서 원자적 진술 집합을 추출하고, 각 진술이 근거에 의해
  지지되는지 검증한 뒤 `지지된 진술 수 / 전체 진술 수`
- *Answer Relevancy*: 답변으로부터 질문을 역생성하고, 원 질문과의 임베딩
  코사인 유사도를 평균

직접 구현한 이유는 세 가지다. (1) 판정 캐싱과 온도 고정을 직접 통제해야 했다.
이미 자체 평가기에서 `temperature=0`에서도 판정이 흔들려 과잉거절이
0.100↔0.200으로 진동하는 문제를 겪었기 때문이다. (2) 의존성 체인이 무거워
현 환경(Python 3.14)에서 설치 안정성을 보장할 수 없었다. (3) 계산식이 논문에
명시돼 있어 값의 의미가 달라지지 않는다.

**측정 조건** — 사람 라벨이 존재하는 25건 중, 거절 응답 10건은 답변 본문이 없어
생성 지표 대상이 아니므로 제외하고 **15건**을 측정했다. 판정 모델
`gpt-4.1-mini`, `temperature=0`, 판정 캐싱 적용(재실행 시 결과 고정).

재현: `python scripts/39_ragas_measure.py` → `python scripts/40_ragas_cases.py`

## 4.3 결과: Faithfulness는 상품불일치 축을 보지 못한다

사람이 상품불일치로 판정한 3건을 faithfulness가 한 건도 걸러내지 못했다.
Faithfulness ≥ 0.8을 통과 기준으로 볼 때:

| | 사람 fail (3건) | 사람 pass (12건) |
|---|---|---|
| Faithfulness < 0.8 | **0** | 4 |
| Faithfulness ≥ 0.8 | **3** | 8 |

재현율 0/3, 오탐 4건. 평균값을 보면 방향 자체가 뒤집혀 있다 —
**fail 항목 평균 0.952 > pass 항목 평균 0.878.**

반면 환각 기준으로는 방향이 맞다(fail 평균 0.819 < pass 평균 0.911, 3건 중 1건 탐지).
즉 faithfulness는 자기가 정의한 구성개념인 *근거 지지도*에는 정상 작동하지만,
*질문↔근거 정합성*이라는 다른 축은 구조적으로 볼 수 없다.

### 사례 A — 근거에 완벽히 충실하지만 질문에 대한 답이 아닌 경우

| 항목 | 내용 |
|---|---|
| 질문 | 자유적금 만기 전에 해지하면 우대금리는 어떻게 되나요? |
| 답변 | 『하나더소호 가맹점 적금』은 만기 해지 시에만 우대금리(최고 연 6.00%)가 적용되며, 중도 해지 시에는 적용되지 않습니다. |
| Faithfulness | **1.000** (진술 2/2 지지) |
| 사람 판정 | 상품불일치 **fail** (환각 pass, 수치정확 pass) |

질문은 자유적금 일반을 물었는데 답변은 특정 상품 하나로 좁혀 답했다. 그런데
그 상품의 설명서가 검색 결과에 실제로 들어 있었으므로, 진술 두 개는 모두 근거에
의해 정확히 지지된다. **Faithfulness 1.000은 틀린 값이 아니다.**

원인은 계산식에 있다. 검증 단계는 (진술, 근거) 쌍만 입력받는다. 질문은 진술 추출
단계에만 관여하고 검증에는 들어가지 않는다. 질문과 근거가 다른 상품을 가리키는
상황은 이 지표의 정의상 관측 불가능하다.

### 사례 B — 원자적 분해가 상품 귀속 정보를 파괴하는 경우

| 항목 | 내용 |
|---|---|
| 질문 | 정기예금을 중도해지하면 이자는 어떻게 계산되나요? |
| 답변 | (정기예금 일반론에 『주택청약예금』의 중도해지 금리 수치를 혼입) |
| Faithfulness | **1.000** (진술 6/6 지지) |
| 사람 판정 | 환각·상품불일치·수치정확 **모두 fail** |

검증기는 "1개월 이내 중도해지는 기본금리의 ½"이라는 진술에 대해 *근거에 해당
수치가 존재한다*는 이유로 지지 판정을 내렸다. **그 수치가 어느 상품의 것인지는
확인하지 않았다.** 답변을 진술 단위로 쪼개는 순간, 각 수치가 어느 상품에
귀속되는지가 검증 대상에서 빠져버린다.

### 부수 발견 — 비율 집계의 희석 효과

세 번째 미탐 사례(상속 주택 관련 질문)에서는 faithfulness가 오류 진술을 **실제로
찾아냈다.** 다만 답변이 7개 진술로 구성돼 있어 6/7 = 0.857이 되었고, 임계값
0.8을 넘어 통과 처리됐다. 답변이 길수록 오류 한 건의 무게가 가벼워지는 구조다.

`지지되지 않은 진술 ≥ 1`이라는 이진 판정을 병행하면 이 건은 포착된다.
다만 사례 A·B는 지지되지 않은 진술이 0건이므로 이진 판정으로도 잡히지 않는다.

## 4.4 반대 방향도 확인했다 — 낮은 점수 3건은 전부 평가 파이프라인 결함

지표를 비판할 때는 반대 방향의 오류도 함께 봐야 한다. Faithfulness가 0.8 미만을
준 항목 중 사람이 문제없다고 판정한 3건을 전수 조사한 결과, **세 건 모두 답변의
결함이 아니라 평가 파이프라인의 결함이었고, 원인이 서로 달랐다.**

| 사례 | 지지되지 않음 판정을 받은 진술 | 실제 원인 |
|---|---|---|
| 디폴트옵션 운용방법 변경 | "포트폴리오 3의 운용방법이 변경된다" | 질문의 **조건절**을 사실 주장으로 오분해. 답변은 "변경 시"라는 전제를 반복했을 뿐 |
| 거치기간 문의 | "보금자리론에는 별도 규정이 없다" | **부재 진술**은 근거로 증명할 수 없음. 근거에 없다고 정직하게 밝힌 답변이 감점됨 |
| 소득공제 장기펀드 중도해지 | "소득공제를 받지 않으면 추징세액이 부과되지 않는다" | 진술 추출기가 원문("환출 가능")을 **의미 왜곡**. 검증기는 왜곡된 진술을 정확히 기각 |

두 번째 사례는 특히 짚어둘 만하다. 근거 부재를 명시하는 답변이 faithfulness에서
벌점을 받는 구조인데, 이는 *근거가 부족하면 답하지 않는다*는 이 시스템의 설계
목표와 정면으로 충돌한다.

**이 결과는 자체 평가기에서 이미 관측한 현상과 같다.** 자체 평가기의 상품불일치
판정을 전수 분류했을 때 20건 중 16건이 답변의 오류가 아니라 평가기의 한계였고,
그 결과 지표를 0.290에서 0.058로 정정했다. 같은 종류의 오탐이 외부 표준
프레임워크에서도 동일하게 발생한다는 것을 이번에 확인했다.

## 4.5 측정했으나 채택하지 않은 지표 — Answer Relevancy

15건 전체가 0.873 ~ 0.949 범위에 몰렸다. 폭이 0.076에 불과하고, 사람이 fail로
판정한 답변들이 정상 답변 사이에 흩어져 있어 어떤 임계값으로도 분리되지 않는다.
한국어 단문 질문 + `multilingual-e5-small` 조합에서 코사인 유사도가 포화된 것으로
보인다.

원 질문과 답변의 정합성을 재는 지표라는 점에서 사례 A를 잡아낼 후보였으나,
해당 항목의 점수는 0.884로 전체 분포 안에 묻혔다. **변별력이 확인되지 않아
지표로 채택하지 않는다.**

## 4.6 이 실험의 한계

- **표본이 작다.** 측정 15건, 사람이 fail로 판정한 항목 3건이다. 통계적 검정력은
  없으며, 비율이 아니라 **메커니즘 수준의 반례**로 제시한다.
- **표본이 대표성을 갖지 않는다.** 이 25건은 자동 평가기 캘리브레이션을 위해
  구성한 셋이라 실패 사례가 의도적으로 농축돼 있다. 여기서 나온 3/15를 실제
  상품불일치율로 읽어서는 안 된다. 전체 96건 기준 실측치는 0.058이다.
- **RAGAs의 나머지 지표는 측정하지 않았다.** Context Precision / Context Recall은
  정답 청크 라벨이 필요해 이번 범위에서 제외했다. 사례 A는 무관한 근거가 상위에
  포함된 경우이므로, 이 두 지표라면 포착했을 가능성이 있다. 이 글의 주장은
  *faithfulness가 이 축을 보지 못한다*는 것이지 *RAGAs 전체가 무력하다*는 것이 아니다.
- **판정 모델 의존성을 분리하지 않았다.** 자체 평가기와 RAGAs 재구현이 같은
  `gpt-4.1-mini`를 사용하므로, 두 평가 체계의 오류가 독립이라고 보장할 수 없다.

## 4.7 결론

표준 지표는 비교 가능성을 위해 필요하고, 도메인 지표는 표준 지표가 보지 못하는
축을 덮기 위해 필요하다. 이 프로젝트는 두 층을 함께 쓴다.

| 층 | 지표 | 역할 |
|---|---|---|
| 표준 | Faithfulness, Recall@k · MRR · NDCG, negative rejection | 외부 비교 가능성 |
| 도메인 | 상품불일치, 수치오류, 오거절 | 표준 지표가 구조적으로 볼 수 없는 축 |

그리고 두 층 모두 **사람 검수로 신뢰도를 측정한 뒤에만** 보고한다. 자동 평가기의
환각 판정은 재설계 전 Cohen's kappa 0.00이었고, 항목별 채점을 분리한 뒤 0.73으로
올랐다. 끝내 자동화하지 못한 2개 항목은 지표에서 제외하고 그 사실을 명시했다.
